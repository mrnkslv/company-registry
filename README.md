# Company Registry

A Go microservice for managing companies. Reading is public; create, update and delete require a JWT.

**Stack:** Go, chi, PostgreSQL (sqlx + pgx), goose migrations, JWT, zap, Swagger, Docker.

## Run

Requirements: Docker with Compose v2.

```bash
docker compose up --build
```

The API is available at `http://localhost:8080`, Swagger UI at
[http://localhost:8080/swagger/index.html](http://localhost:8080/swagger/index.html).
Migrations are applied automatically on startup.

To run the service locally with Go 1.27+, start only the database and run the app:

```bash
docker compose up -d db
go run ./cmd
```

## Usage

A test user is created by the migrations: `testusername` / `password1`.

```bash
# get a token
TOKEN=$(curl -s -X POST localhost:8080/auth/v1/login \
  -d '{"username":"testusername","password":"password1"}' | jq -r .token)

# create
curl -X POST localhost:8080/company/v1/ -H "Authorization: Bearer $TOKEN" \
  -d '{"name":"Acme","type":"Corporations","amount_of_employees":10,"registered":true}'

# get, patch, delete
curl localhost:8080/company/v1/<id>
curl -X PATCH localhost:8080/company/v1/<id> -H "Authorization: Bearer $TOKEN" -d '{"registered":false}'
curl -X DELETE localhost:8080/company/v1/<id> -H "Authorization: Bearer $TOKEN"
```

| Method | Path | Auth |
|---|---|---|
| `POST` | `/auth/v1/login` | – |
| `GET` | `/company/v1/{id}` | – |
| `POST` | `/company/v1/` | ✓ |
| `PATCH` | `/company/v1/{id}` | ✓ |
| `DELETE` | `/company/v1/{id}` | ✓ |

**Company fields:** `name` (required, ≤ 15 chars, unique), `description` (optional, ≤ 3000 chars),
`amount_of_employees` (required, > 0), `registered` (bool), `type` (`Corporations`, `NonProfit`, `Cooperative`,
`Sole Proprietorship`). The `id` is generated by the service. `PATCH` updates only the fields that are sent.

Errors are returned as `{"code": 404, "type": "Not found", "message": "..."}` with status `400`, `401`, `404`, `409`
or `500`.

## Configuration

Settings come from environment variables; a `.env` file is loaded if present.

The `.env` file is **committed on purpose** so the project runs without any setup. It contains only local development
values. In production, secrets must come from the environment (orchestrator secrets, vault, etc.) and `.env` should be
added to `.gitignore`.

| Variable | Default |
|---|---|
| `HTTP_LISTEN_ADDRESS` | required |
| `PG_DSN_COMPANY_REGISTRY` | required |
| `AUTH_SALT` | required |
| `AUTH_SIGNING_KEY` | required |
| `AUTH_TOKEN_TTL` | `12h` |
| `DEBUG` | `false` |

HTTP timeouts and Postgres pool sizes are also configurable, see `internal/config/config.go`.

```bash
make test-integration   # integration tests: real Postgres via testcontainers (requires Docker)

```

## Known limitations

Authentication is intentionally minimal: one test user, no registration, no refresh tokens or roles.
Passwords use SHA-1 with a static salt; a real system would use bcrypt or argon2.
